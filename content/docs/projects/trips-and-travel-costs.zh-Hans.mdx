# 出差与差旅成本

**出差申请**（`crm_business_trip`）是申请：谁出差、去哪、何时、为哪个项目、预计花多少。**差旅成本**（`crm_travel_cost`）是事后对着那次出差登记的一笔开销——机票、一晚住宿、一程打车——也是落到项目上成为**差旅实际**的东西。顺序是刻意的：出差先审批，成本只能对着已审批的出差登记。

## 出差申请

| 字段 | 含义 |
| --- | --- |
| 事由、出差人 | 出差为了什么、谁去 |
| 交付项目 *或* 售前项目 | 成本算谁的——二选一 |
| 目的地、交通方式（*飞机、火车、汽车、其他*）、起止日期、天数 | 计划；天数由 `business_trip_days_fill` 按日期算出 |
| 预计费用 | 出差人预计要花的 |
| 实际费用 | 汇总——记到这次出差上的差旅成本之和；不用手填 |
| 审批状态*（只读）*、审批日期 | **出差审批**的结论，由项目经理决定 |

用**发起审批**提交出差；记录锁定直到项目经理决定，平时状态字段只读。已启用附件，行程单或客户邀请函作为附件放在记录上。

## 差旅成本

| 字段 | 含义 |
| --- | --- |
| 关联出差 | 这笔成本所属的、已审批的出差 |
| 交付项目、出差人、日期 | 由 `travel_cost_trip_fill` 从出差带入；只有交付项目计入差旅实际 |
| 类别、金额、票据号、备注 | 开销本身 |

## 系统自动做的事

- **出差门禁。** 对着尚未审批通过的出差保存差旅成本会被**拒绝**：*出差申请「…」尚未审批通过，不能登记差旅成本*。先批出差，再登记成本。
- **从出差带入默认值**（`travel_cost_trip_fill`）——成本留空的项目、出差人和日期从出差复制过来，所以一笔成本不会意外落到与出差不同的项目上。
- **两个汇总**——出差的实际费用汇总它的成本，交付项目的差旅实际汇总记到它上面的每一笔成本；[交付项目](/zh-Hans/docs/projects/delivery-projects)上的实际成本与预算消耗随之变化。

## 共享

出差申请是**私有**的——出差人自己的申请，销售经理和系统管理员看全部；审批人通过审批请求到达它，而不是通过共享。差旅成本在交付项目下*由父级控制*：看得到项目的人看得到它的差旅成本。

## 提示

- ✅ **出发前先提申请**，回来当天成本就能登记。
- ✅ **一张票据一条差旅成本**，带上票据号——那是财务对账的自然键。
- ✅ **盯着出差上的预计与实际费用**：那是项目差旅线跑热的最早信号。
