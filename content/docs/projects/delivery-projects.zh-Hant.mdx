# 交付專案 [#delivery-projects]

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**交付專案**（`crm_delivery_project`）是贏單之後真正做的那個專案。它回鏈到售前專案、商機、客戶和銷售合約，也是本模組裡所有東西彙總的終點：[**成本計畫**](/zh-Hant/docs/projects/cost-plans)、**預算調整**、工時表、差旅成本、開票、收款、採購合約和銷售訂單。

## 交付專案記錄存什麼 [#what-a-delivery-project-record-stores]

| 分組 | 內容 |
| --- | --- |
| **專案資訊** | 名稱、別名、售前專案、商機、客戶、狀態（*規劃中 / 進行中 / 已關閉*）、計畫起訖日期、描述 |
| **成本中心與部門** | 實施成本中心、核算成本中心、部門 |
| **專案角色** | 專案經理、專案總監、資源報價負責人、分包 TS 負責人、QA 負責人 |
| **預算與實際** | 預算基線、已核准調整、目前預算、計畫總額、人工實際、差旅實際、實際成本、預算消耗 |
| **合約與財務** | 銷售合約、合約額、進度、已確認收入、已開票、已收款、應收餘額、採購合約合計、銷售訂單合計、專案毛利率 |
| **審批** | 審批狀態*（唯讀）*、審批日期 |

大部分金額欄位是**彙總或公式**，不能手填：

- **已核准調整**彙總*已通過*的預算調整；**目前預算**＝基線＋這個和。
- **計畫總額**是專案*目前*[成本計畫](/zh-Hant/docs/projects/cost-plans)版本的總額；**人工實際**彙總*已審批*工時表的成本；**差旅實際**彙總記到專案上的差旅成本；**實際成本**是兩者之和；**預算消耗**＝實際 ÷ 基線。
- **已確認收入**＝合約額 × 進度；**應收餘額**＝已開票 − 已收款；**專案毛利率**＝（合約額 − 實際成本）÷ 合約額。
- **已開票**不計*作廢*的發票，**採購合約合計**不計*已終止*的合約，所以一份單據一改狀態就立刻不再計入。

## 成本計畫 [#the-cost-plan]

交付專案的預算在它的[**成本計畫**](/zh-Hant/docs/projects/cost-plans)上做：四類明細行（人工、第三方服務、採購、費用），每一條都由系統分解成逐月台帳，並且帶版本，所以已審批的計畫從不被原地改動。專案上的**導入 Bizcase 預算**從已審批的售前 Bizcase 生成第 1 版並凍結基線；專案上的**計畫總額**讀的是目前生效的版本。

## 預算調整 [#budget-adjustments]

**預算調整**（`crm_budget_adjustment`）是在某一個專案上申請追加（或核減）預算：原因（*範圍變更、工期延長、費率變化、風險應對、其他*）、分析說明，以及——通常情況下——它要使之生效的新成本計畫版本，調整金額就從那裡讀出（新總額減去生效中版本的總額）。沒掛版本的調整直接填金額。它由**預算調整審批**流程審批——記錄上**發起審批**，財務負責人決定——只有*已通過*的調整才會動專案的目前預算、並讓它掛的計畫版本成為目前版本。草稿或被駁回的調整什麼都不改。

## 系統自動做的事 [#what-the-system-does-automatically]

### 新建時——從 Bizcase 取預設值 [#on-create--defaults-from-the-bizcase]
新建交付專案時若填了售前專案而**預算基線留空**，基線就預設取該售前專案的總成本，合約額取銷售合約的合約金額（`delivery_project_defaults`）。自己填了基線就用你填的。真正算數的基線，是**導入 Bizcase 預算**連同成本計畫 v1 一起凍結的那一個——見下文。

同一步也會在**商機**和**客戶**留空時，把它們從該售前專案帶過來（客戶也可以跟隨銷售合約）。這兩項是在**儲存記錄時**填上的，不是在你選完售前專案的那一刻，所以新建表單上它們會一直是空的，直到你點了建立——之後打開這筆記錄就能看到。自己選了就用你選的。

### 匯入 Bizcase [#importing-the-bizcase]
記錄頂部的**導入 Bizcase 預算**——需求的第 27 步——取售前專案目前的 Bizcase 成本計畫（必須*已通過*），把它的明細行克隆為本專案的成本計畫 v1——Bizcase 整段估算、不分月，交付計畫在明細行落地時逐條按月分解——並把 Bizcase 總額寫成計畫的凍結基線和專案的預算基線。已經有計畫的專案、未通過的售前專案、沒有計畫的 Bizcase，它都拒絕。種子回放和其它系統寫入從不觸發它。

### 預算門禁 [#the-budget-gate]
專案的**實際成本達到目前預算**後就不能再對它填工時：儲存會被拒絕，提示裡帶專案名和兩個數字——*项目「…」成本已超预算（实际 … ≥ 预算 …），工时填报已限制*。剩餘預算不夠的那一張也一樣：新建時成本超過**目前預算 − 實際成本**的工時表會被拒絕——*项目「…」预算剩余 …，本次工时成本 … 已超出剩余预算，工时填报已限制；请调减工时，或先提交预算调整并审批通过*。門禁量的是**目前預算**，所以出路是一條審批通過的預算調整，它抬高目前預算；見[工時與請假](/zh-Hant/docs/projects/timesheets-and-leave)。

### 審批 [#approval]
專案由**交付立項審批**流程審批，從**發起審批**按鈕發起，由高階主管決定。和本模組其它地方一樣，狀態欄位唯讀，審批未結時記錄鎖定。

## 共用 [#sharing]

交付專案和售前專案一樣是**私有**的：負責人看自己的；記錄上的專案角色欄位本身不授予任何權限——被填成專案經理並不等於能看到它。銷售經理和系統管理員看全部。每一個*由父層控制*的子物件（差旅成本、預算調整、開票、收款、採購合約、銷售訂單）都跟隨專案自身的可見性；[成本計畫](/zh-Hant/docs/projects/cost-plans)則是其成本管理員的私有記錄，它的明細行跟隨計畫。[工時表](/zh-Hant/docs/projects/timesheets-and-leave)不在此列：交付專案在工時表上是可選的，所以一張表歸填報人私有。

## 給專案經理的提示 [#tips-for-project-managers]

- ✅ **專案開了就匯入 Bizcase**，然後到計畫自己的記錄上細化明細行和月份；凍結基線原地不動。
- ✅ **盯著 [Project Cost 儀表板](/zh-Hant/docs/analytics/dashboards)上的預算消耗**——到 100% 的專案就是沒人能再填工時的專案。
- ✅ **最後一筆款收到後把專案置為*已關閉***；已關閉的專案仍計入儀表板的合計。
