# 交付專案

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**交付專案**（`crm_delivery_project`）是贏單之後真正做的那個專案。它回鏈到售前專案、商機、客戶和銷售合約，也是本模組裡所有東西彙總的終點：**成本計畫行**、**預算調整**、工時表、差旅成本、開票、收款、採購合約和銷售訂單。

## 交付專案記錄存什麼

| 分組 | 內容 |
| --- | --- |
| **專案資訊** | 名稱、別名、售前專案、商機、客戶、狀態（*規劃中 / 進行中 / 已關閉*）、計畫起訖日期、描述 |
| **成本中心與部門** | 實施成本中心、核算成本中心、部門 |
| **專案角色** | 專案經理、專案總監、資源報價負責人、分包 TS 負責人、QA 負責人 |
| **預算與實際** | 預算基線、已核准調整、目前預算、計畫總額、人工實際、差旅實際、實際成本、預算消耗 |
| **合約與財務** | 銷售合約、合約額、進度、已確認收入、已開票、已收款、應收餘額、採購合約合計、銷售訂單合計、專案毛利率 |
| **審批** | 審批狀態*（唯讀）*、審批日期 |

大部分金額欄位是**彙總或公式**，不能手填：

- **已核准調整**彙總*已通過*的預算調整；**目前預算**＝基線＋這個和。
- **計畫總額**彙總成本計畫行；**人工實際**彙總*已審批*工時表的成本；**差旅實際**彙總記到專案上的差旅成本；**實際成本**是兩者之和；**預算消耗**＝實際 ÷ 基線。
- **已確認收入**＝合約額 × 進度；**應收餘額**＝已開票 − 已收款；**專案毛利率**＝（合約額 − 實際成本）÷ 合約額。
- **已開票**不計*作廢*的發票，**採購合約合計**不計*已終止*的合約，所以一份單據一改狀態就立刻不再計入。

## 成本計畫行

**成本計畫行**（`crm_cost_plan_line`）是專案上一條做了預算的項目：類別（人工、第三方服務、採購、費用）、描述、數量、單價與計畫金額。它在交付專案的記錄頁上編輯——沒有側邊欄項目，也沒有自己的可見性：計畫行是*由父層控制*的，看得到專案的人就看得到它的計畫行。

**人工**行上選了[費率卡](/zh-Hant/docs/projects/master-data)裡的職級，單價就從那張卡帶入（`cost_plan_line_fill`）；計畫金額隨之＝數量 × 單價。

## 預算調整

**預算調整**（`crm_budget_adjustment`）是在某一個專案上申請追加（或核減）預算：金額、原因（*範圍變更、工期延長、費率變化、風險應對、其他*）和分析說明。它由**預算調整審批**流程審批——記錄上**發起審批**，財務負責人決定——只有*已通過*的調整才會動專案的目前預算。草稿或被駁回的調整什麼都不改。

## 系統自動做的事

### 新建時——從 Bizcase 取預設值
新建交付專案時若填了售前專案而**預算基線留空**，基線就取該售前專案的總成本，合約額取銷售合約的合約金額（`delivery_project_defaults`）。自己填了基線就用你填的。

同一步也會在**商機**和**客戶**留空時，把它們從該售前專案帶過來（客戶也可以跟隨銷售合約）。這兩項是在**儲存記錄時**填上的，不是在你選完售前專案的那一刻，所以新建表單上它們會一直是空的，直到你點了建立——之後打開這筆記錄就能看到。自己選了就用你選的。

### 新建時——帶入成本計畫
緊接著，若售前專案*已通過*且基線正好等於它的總成本，Bizcase 的四項成本會作為四條成本計畫行帶入——人工、第三方服務、採購、費用——各自帶著 Bizcase 的金額（`delivery_project_cost_plan_carry`）。未通過的 Bizcase、手填的基線、或者種子回放這類系統寫入，都不帶。

### 預算門禁
專案的**實際成本達到目前預算**後就不能再對它填工時：儲存會被拒絕，提示裡帶專案名和兩個數字——*项目「…」成本已超预算（实际 … ≥ 预算 …），工时填报已限制*。剩餘預算不夠的那一張也一樣：新建時成本超過**目前預算 − 實際成本**的工時表會被拒絕——*项目「…」预算剩余 …，本次工时成本 … 已超出剩余预算，工时填报已限制；请调减工时，或先提交预算调整并审批通过*。門禁量的是**目前預算**，所以出路是一條審批通過的預算調整，它抬高目前預算；見[工時與請假](/zh-Hant/docs/projects/timesheets-and-leave)。

### 審批
專案由**交付立項審批**流程審批，從**發起審批**按鈕發起，由高階主管決定。和本模組其它地方一樣，狀態欄位唯讀，審批未結時記錄鎖定。

## 共用

交付專案和售前專案一樣是**私有**的：負責人看自己的；記錄上的專案角色欄位本身不授予任何權限——被填成專案經理並不等於能看到它。銷售經理和系統管理員看全部。每一個*由父層控制*的子物件（成本計畫行、差旅成本、預算調整、開票、收款、採購合約、銷售訂單）都跟隨專案自身的可見性。[工時表](/zh-Hant/docs/projects/timesheets-and-leave)不在此列：交付專案在工時表上是可選的，所以一張表歸填報人私有。

## 給專案經理的提示

- ✅ **第一次儲存時把基線留空**，讓 Bizcase 的數字和四條計畫行進來；之後再改計畫行。
- ✅ **盯著[專案成本儀表板](/zh-Hant/docs/analytics/dashboards)上的預算消耗**——到 100% 的專案就是沒人能再填工時的專案。
- ✅ **最後一筆款收到後把專案置為*已關閉***；已關閉的專案仍計入儀表板的合計。
