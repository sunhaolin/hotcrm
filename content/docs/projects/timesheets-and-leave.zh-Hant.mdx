# 工時與請假

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**工時表**（`crm_timesheet`）是一個人在一個專案上一個月的工時，也是把這些工時變成**人工成本**的那條記錄。**請假申請**（`crm_leave_request`）是讓這個月變短的缺勤，審批通過後會自己寫進工時表的請假工時。

## 工時表記錄存什麼

| 欄位 | 含義 |
| --- | --- |
| 填報人、月份 | 誰的工時、哪個月——每人每專案每月一張 |
| 交付專案 *或* 售前專案 | 工時記在哪裡；記在售前專案上的表彙總進那次投標的售前工時 |
| 職級 / 費率卡 | 給工時計價的那行[費率卡](/zh-Hant/docs/projects/master-data) |
| 小時費率 | 從費率卡帶入 |
| 標準工時、請假工時、加班工時、工時 | 這個月的算術——見下 |
| 成本 | 工時 × 小時費率 |
| 審批狀態*（唯讀）*、審批日期 | **工時審批**的結論 |

## 系統自動做的事

每次儲存依次跑四個 hook：

1. **費率帶入**（`timesheet_rate_fill`）——選了職級，就把那張費率卡的小時費率複製到表上，所以費率卡改了只影響新表，不動已審批的歷史。
2. **考勤同步**（`timesheet_attendance_sync`）——*草稿*表上，**工時 = 標準工時 − 請假工時 + 加班工時**。標準工時是這個月應出的工時；請假和加班讓數字上下。提交之後工時就定了。
3. **成本計算**（`timesheet_cost_fill`）——**成本 = 工時 × 小時費率**，兩者任一改動都重算。
4. **預算門禁**（`timesheet_budget_gate`）——對一個實際成本已經達到預算基線的交付專案填表，會被**拒絕**：*项目「…」成本已超预算（实际 … ≥ 基线 …），工时填报已限制*。專案要先有一條審批通過的[預算調整](/zh-Hant/docs/projects/delivery-projects)，才能再往上記工時。

### 審批，以及什麼算數
點**發起審批**；銷售經理決定；狀態欄位平時唯讀。**只有已審批的工時表才是人工成本**：交付專案的人工實際、售前專案的售前人工實際、專案成本儀表板，彙總的都是已審批的表，別的一律不算。草稿是計畫，被駁回的什麼都不是。

## 請假申請

請假申請帶一個類型（*年假、病假、事假、調休、婚假、產假、其他*）、起訖日期、兩者之間的天數——由 `leave_days_fill` 算出，不用手填——以及可選的、缺勤影響到的交付專案。它由**請假審批**流程審批（部門負責人）。

### 請假進工時表
請假申請**審批通過**時，`leave_timesheet_sync` 會找到申請人當月的工時表，把請假寫進它的**請假工時**；上面的考勤同步隨即拉低當月工時，成本跟著變。還在審批中或被駁回的請假不碰任何工時表。

## 共用

工時表*由父層控制*：看得到交付專案的人看得到它的工時表，別人看不到——打不開專案的代表也打不開記在它上面的表。請假申請是**私有**的：申請人自己的，外加銷售經理和系統管理員看全部。

## 提示

- ✅ **一個月一張表，月底提交。** 記到超預算專案上的工時會被彈回來；先申請調整。
- ✅ **在工時表提交之前把假請掉。** 之後才通過的請假不會重新開啟已提交的表。
- ✅ **投標的工作記到售前專案上**，它才會出現在投標的售前人工實際裡，而不是某個交付專案上。
