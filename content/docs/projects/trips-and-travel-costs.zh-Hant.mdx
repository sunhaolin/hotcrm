# 出差與差旅成本

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**出差申請**（`crm_business_trip`）是申請：誰出差、去哪、何時、為哪個專案、預計花多少。**差旅成本**（`crm_travel_cost`）是事後對著那次出差登記的一筆開銷——機票、一晚住宿、一程搭車——也是落到專案上成為**差旅實際**的東西。順序是刻意的：出差先審批，成本只能對著已審批的出差登記。

## 出差申請

| 欄位 | 含義 |
| --- | --- |
| 事由、出差人 | 出差為了什麼、誰去 |
| 交付專案 *或* 售前專案 | 成本算誰的——二選一 |
| 目的地、交通方式（*飛機、火車、汽車、其他*）、起訖日期、天數 | 計畫；天數由 `business_trip_days_fill` 按日期算出 |
| 預計費用 | 出差人預計要花的 |
| 實際費用 | 彙總——記到這次出差上的差旅成本之和；不用手填 |
| 審批狀態*（唯讀）*、審批日期 | **出差審批**的結論，由專案經理決定 |

用**發起審批**提交出差；記錄鎖定直到專案經理決定，平時狀態欄位唯讀。已啟用附件，行程單或客戶邀請函作為附件放在記錄上。

## 差旅成本

| 欄位 | 含義 |
| --- | --- |
| 關聯出差 | 這筆成本所屬的、已審批的出差 |
| 交付專案、出差人、日期 | 由 `travel_cost_trip_fill` 從出差帶入；只有交付專案計入差旅實際 |
| 類別、金額、票據號、備註 | 開銷本身 |

## 系統自動做的事

- **出差門禁。** 對著尚未審批通過的出差儲存差旅成本會被**拒絕**：*出差申请「…」尚未审批通过，不能登记差旅成本*。先批出差，再登記成本。
- **從出差帶入預設值**（`travel_cost_trip_fill`）——成本留空的專案、出差人和日期從出差複製過來，所以一筆成本不會意外落到與出差不同的專案上。
- **兩個彙總**——出差的實際費用彙總它的成本，交付專案的差旅實際彙總記到它上面的每一筆成本；[交付專案](/zh-Hant/docs/projects/delivery-projects)上的實際成本與預算消耗隨之變化。

## 共用

出差申請是**私有**的——出差人自己的申請，銷售經理和系統管理員看全部；審批人透過審批請求到達它，而不是透過共用。差旅成本在交付專案下*由父層控制*：看得到專案的人看得到它的差旅成本。

## 提示

- ✅ **出發前先提申請**，回來當天成本就能登記。
- ✅ **一張票據一條差旅成本**，帶上票據號——那是財務對帳的自然鍵。
- ✅ **盯著出差上的預計與實際費用**：那是專案差旅線跑熱的最早訊號。
