# 工时与请假

**工时表**（`crm_timesheet`）是一个人在一个项目上一个月的工时，也是把这些工时变成**人工成本**的那条记录。**请假申请**（`crm_leave_request`）是让这个月变短的缺勤，审批通过后会自己写进工时表的请假工时。

## 工时表记录存什么

| 字段 | 含义 |
| --- | --- |
| 填报人、月份 | 谁的工时、哪个月——每人每项目每月一张 |
| 交付项目 *或* 售前项目 | 工时记在哪里——两者都可选：记在售前项目上的表汇总进那次投标的售前工时，两个都不填的表只记考勤 |
| 岗位级别 / 费率卡 | 给工时计价的那行[费率卡](/zh-Hans/docs/projects/master-data) |
| 小时费率 | 从费率卡带入——只读，新建和编辑时都不出现在表单上 |
| 标准工时、请假工时、加班工时、工时 | 这个月的算术——见下 |
| 成本 | 工时 × 小时费率——只读，新建和编辑时都不出现在表单上 |
| 审批状态*（只读）*、审批日期 | **工时审批**的结论 |

## 系统自动做的事

每次保存依次跑四个钩子：

1. **费率带入**（`timesheet_rate_fill`）——选了岗位级别，就把那张费率卡的小时费率复制到表上。费率只有这一个来源：没人手填，已经计过价的表也保留原费率，所以费率卡改了只影响新表，不动已审批的历史。
2. **考勤同步**（`timesheet_attendance_sync`）——*草稿*表上，**工时 = 标准工时 − 请假工时 + 加班工时**。标准工时是这个月应出的工时；请假和加班让数字上下。提交之后工时就定了。
3. **成本计算**（`timesheet_cost_fill`）——**成本 = 工时 × 小时费率**，两者任一改动都重算。
4. **预算门禁**（`timesheet_budget_gate`）——预算付不起的工时表，在**新建保存的那一刻**就被拒绝。两种情形：项目实际成本已经达到当前预算——*项目「…」成本已超预算（实际 … ≥ 预算 …），工时填报已限制*；或者预算还有剩余，但不够这张表的成本——*项目「…」预算剩余 …，本次工时成本 … 已超出剩余预算，工时填报已限制；请调减工时，或先提交预算调整并审批通过*。控制线是**当前预算**：预算基线加上全部审批通过的[预算调整](/zh-Hans/docs/projects/delivery-projects)，所以一条审批通过的预算调整就是继续填报的出路。完全没有预算的项目不受门禁约束。

### 审批，以及什么算数
点**发起审批**；销售经理决定；状态字段平时只读。**只有已审批的工时表才是人工成本**：交付项目的人工实际、售前项目的售前人工实际、项目成本仪表板，汇总的都是已审批的表，别的一律不算。草稿是计划，被驳回的什么都不是。

## 请假申请

请假申请带一个类型（*年假、病假、事假、调休、婚假、产假、其他*）、起止日期、两者之间的天数——由 `leave_days_fill` 算出，不用手填——以及可选的、缺勤影响到的交付项目。它由**请假审批**流程审批（部门负责人）。

### 请假进工时表
请假申请**审批通过**时，`leave_timesheet_sync` 会找到申请人当月的工时表，把请假写进它的**请假工时**；上面的考勤同步随即拉低当月工时，成本跟着变。还在审批中或被驳回的请假不碰任何工时表。

## 共享

工时表和请假申请一样是**私有**的：填报人自己的表，外加做**工时审批**的销售经理和系统管理员看全部。在交付项目变成可选之前，工时表是在它下面*由父级控制*的；一条可以不填父记录的记录，没有父记录可供派生可见性。

## 提示

- ✅ **一个月一张表，月底提交。** 剩余预算不够的工时，保存时就会被弹回来；先申请调整。
- ✅ **在工时表提交之前把假请掉。** 之后才通过的请假不会重新打开已提交的表。
- ✅ **投标的工作记到售前项目上**，它才会出现在投标的售前人工实际里，而不是某个交付项目上。
