# 交付项目 [#delivery-projects]

**交付项目**（`crm_delivery_project`）是赢单之后真正做的那个项目。它回链到售前项目、商机、客户和销售合同，也是本模块里所有东西汇总的终点：[**成本计划**](/zh-Hans/docs/projects/cost-plans)、**预算调整**、工时表、差旅成本、开票、收款、采购合同和销售订单。

## 交付项目记录存什么 [#what-a-delivery-project-record-stores]

| 分组 | 内容 |
| --- | --- |
| **项目信息** | 名称、别名、售前项目、商机、客户、状态（*规划中 / 进行中 / 已关闭*）、计划起止日期、描述 |
| **成本中心与部门** | 实施成本中心、核算成本中心、部门 |
| **项目角色** | 项目经理、项目总监、资源报价负责人、分包 TS 负责人、QA 负责人 |
| **预算与实际** | 预算基线、已批准调整、当前预算、计划总额、人工实际、差旅实际、实际成本、预算消耗 |
| **合同与财务** | 销售合同、合同额、进度、已确认收入、已开票、已收款、应收余额、采购合同合计、销售订单合计、项目毛利率 |
| **审批** | 审批状态*（只读）*、审批日期 |

大部分金额字段是**汇总或公式**，不能手填：

- **已批准调整**汇总*已通过*的预算调整；**当前预算**＝基线＋这个和。
- **计划总额**是项目*当前*[成本计划](/zh-Hans/docs/projects/cost-plans)版本的总额；**人工实际**汇总*已审批*工时表的成本；**差旅实际**汇总记到项目上的差旅成本；**实际成本**是两者之和；**预算消耗**＝实际 ÷ 基线。
- **已确认收入**＝合同额 × 进度；**应收余额**＝已开票 − 已收款；**项目毛利率**＝（合同额 − 实际成本）÷ 合同额。
- **已开票**不计*作废*的发票，**采购合同合计**不计*已终止*的合同，所以一份单据一改状态就立刻不再计入。

## 成本计划 [#the-cost-plan]

交付项目的预算在它的[**成本计划**](/zh-Hans/docs/projects/cost-plans)上做：四类明细行（人工、第三方服务、采购、费用），每一条都由系统分解成逐月台账，并且带版本，所以已审批的计划从不被原地改动。项目上的**导入 Bizcase 预算**从已审批的售前 Bizcase 生成第 1 版并冻结基线；项目上的**计划总额**读的是当前生效的版本。

## 预算调整 [#budget-adjustments]

**预算调整**（`crm_budget_adjustment`）是在某一个项目上申请追加（或核减）预算：原因（*范围变更、工期延长、费率变化、风险应对、其他*）、分析说明，以及——通常情况下——它要使之生效的新成本计划版本，调整金额就从那里读出（新总额减去生效中版本的总额）。没挂版本的调整直接填金额。它由**预算调整审批**流程审批——记录上**发起审批**，财务负责人决定——只有*已通过*的调整才会动项目的当前预算、并让它挂的计划版本成为当前版本。草稿或被驳回的调整什么都不改。

## 系统自动做的事 [#what-the-system-does-automatically]

### 新建时——从 Bizcase 取默认值 [#on-create--defaults-from-the-bizcase]
新建交付项目时若填了售前项目而**预算基线留空**，基线就默认取该售前项目的总成本，合同额取销售合同的合同金额（`delivery_project_defaults`）。自己填了基线就用你填的。真正算数的基线，是**导入 Bizcase 预算**连同成本计划 v1 一起冻结的那一个——见下文。

同一步也会在**商机**和**客户**留空时，把它们从该售前项目带过来（客户也可以跟随销售合同）。这两项是在**保存记录时**填上的，不是在你选完售前项目的那一刻，所以新建表单上它们会一直是空的，直到你点了创建——之后打开这条记录就能看到。自己选了就用你选的。

### 导入 Bizcase [#importing-the-bizcase]
记录顶部的**导入 Bizcase 预算**——需求的第 27 步——取售前项目当前的 Bizcase 成本计划（必须*已通过*），把它的明细行克隆为本项目的成本计划 v1——Bizcase 整段估算、不分月，交付计划在明细行落地时逐条按月分解——并把 Bizcase 总额写成计划的冻结基线和项目的预算基线。已经有计划的项目、未通过的售前项目、没有计划的 Bizcase，它都拒绝。种子回放和其它系统写入从不触发它。

### 预算门禁 [#the-budget-gate]
项目的**实际成本达到当前预算**后就不能再对它填工时：保存会被拒绝，提示里带项目名和两个数字——*项目「…」成本已超预算（实际 … ≥ 预算 …），工时填报已限制*。剩余预算不够的那一张也一样：新建时成本超过**当前预算 − 实际成本**的工时表会被拒绝——*项目「…」预算剩余 …，本次工时成本 … 已超出剩余预算，工时填报已限制；请调减工时，或先提交预算调整并审批通过*。门禁量的是**当前预算**，所以出路是一条审批通过的预算调整，它抬高当前预算；见[工时与请假](/zh-Hans/docs/projects/timesheets-and-leave)。

### 审批 [#approval]
项目由**交付立项审批**流程审批，从**发起审批**按钮发起，由高管决定。和本模块其它地方一样，状态字段只读，审批未结时记录锁定。

## 共享 [#sharing]

交付项目和售前项目一样是**私有**的：负责人看自己的；记录上的项目角色字段本身不授予任何权限——被填成项目经理并不等于能看到它。销售经理和系统管理员看全部。每一个*由父级控制*的子对象（差旅成本、预算调整、开票、收款、采购合同、销售订单）都跟随项目自身的可见性；[成本计划](/zh-Hans/docs/projects/cost-plans)则是其成本管理员的私有记录，它的明细行跟随计划。[工时表](/zh-Hans/docs/projects/timesheets-and-leave)不在此列：交付项目在工时表上是可选的，所以一张表归填报人私有。

## 给项目经理的提示 [#tips-for-project-managers]

- ✅ **项目开了就导入 Bizcase**，然后到计划自己的记录上细化明细行和月份；冻结基线原地不动。
- ✅ **盯着 [Project Cost 仪表板](/zh-Hans/docs/analytics/dashboards)上的预算消耗**——到 100% 的项目就是没人能再填工时的项目。
- ✅ **最后一笔款收到后把项目置为*已关闭***；已关闭的项目仍计入仪表板的合计。
