# 交付项目

**交付项目**（`crm_delivery_project`）是赢单之后真正做的那个项目。它回链到售前项目、商机、客户和销售合同，也是本模块里所有东西汇总的终点：**成本计划行**、**预算调整**、工时表、差旅成本、开票、收款、采购合同和销售订单。

## 交付项目记录存什么

| 分组 | 内容 |
| --- | --- |
| **项目信息** | 名称、别名、售前项目、商机、客户、状态（*规划中 / 进行中 / 已关闭*）、计划起止日期、描述 |
| **成本中心与部门** | 实施成本中心、核算成本中心、部门 |
| **项目角色** | 项目经理、项目总监、资源报价负责人、分包 TS 负责人、QA 负责人 |
| **预算与实际** | 预算基线、已批准调整、当前预算、计划总额、人工实际、差旅实际、实际成本、预算消耗 |
| **合同与财务** | 销售合同、合同额、进度、已确认收入、已开票、已收款、应收余额、采购合同合计、销售订单合计、项目毛利率 |
| **审批** | 审批状态*（只读）*、审批日期 |

大部分金额字段是**汇总或公式**，不能手填：

- **已批准调整**汇总*已通过*的预算调整；**当前预算**＝基线＋这个和。
- **计划总额**汇总成本计划行；**人工实际**汇总*已审批*工时表的成本；**差旅实际**汇总记到项目上的差旅成本；**实际成本**是两者之和；**预算消耗**＝实际 ÷ 基线。
- **已确认收入**＝合同额 × 进度；**应收余额**＝已开票 − 已收款；**项目毛利率**＝（合同额 − 实际成本）÷ 合同额。
- **已开票**不计*作废*的发票，**采购合同合计**不计*已终止*的合同，所以一份单据一改状态就立刻不再计入。

## 成本计划行

**成本计划行**（`crm_cost_plan_line`）是项目上一条做了预算的项目：类别（人工、第三方服务、采购、费用）、描述、数量、单价与计划金额。它在交付项目的记录页上编辑——没有侧边栏条目，也没有自己的可见性：计划行是*由父级控制*的，看得到项目的人就看得到它的计划行。

**人工**行上选了[费率卡](/zh-Hans/docs/projects/master-data)里的岗位级别，单价就从那张卡带入（`cost_plan_line_fill`）；计划金额随之＝数量 × 单价。

## 预算调整

**预算调整**（`crm_budget_adjustment`）是在某一个项目上申请追加（或核减）预算：金额、原因（*范围变更、工期延长、费率变化、风险应对、其他*）和分析说明。它由**预算调整审批**流程审批——记录上**发起审批**，财务负责人决定——只有*已通过*的调整才会动项目的当前预算。草稿或被驳回的调整什么都不改。

## 系统自动做的事

### 新建时——从 Bizcase 取默认值
新建交付项目时若填了售前项目而**预算基线留空**，基线就取该售前项目的总成本，合同额取销售合同的合同金额（`delivery_project_defaults`）。自己填了基线就用你填的。

### 新建时——带入成本计划
紧接着，若售前项目*已通过*且基线正好等于它的总成本，Bizcase 的四项成本会作为四条成本计划行带入——人工、第三方服务、采购、费用——各自带着 Bizcase 的金额（`delivery_project_cost_plan_carry`）。未通过的 Bizcase、手填的基线、或者种子回放这类系统写入，都不带。

### 预算门禁
项目的**实际成本达到当前预算**后就不能再对它填工时：保存会被拒绝，提示里带项目名和两个数字——*项目「…」成本已超预算（实际 … ≥ 预算 …），工时填报已限制*。剩余预算不够的那一张也一样：新建时成本超过**当前预算 − 实际成本**的工时表会被拒绝——*项目「…」预算剩余 …，本次工时成本 … 已超出剩余预算，工时填报已限制；请调减工时，或先提交预算调整并审批通过*。门禁量的是**当前预算**，所以出路是一条审批通过的预算调整，它抬高当前预算；见[工时与请假](/zh-Hans/docs/projects/timesheets-and-leave)。

### 审批
项目由**交付立项审批**流程审批，从**发起审批**按钮发起，由高管决定。和本模块其它地方一样，状态字段只读，审批未结时记录锁定。

## 共享

交付项目和售前项目一样是**私有**的：负责人看自己的；记录上的项目角色字段本身不授予任何权限——被填成项目经理并不等于能看到它。销售经理和系统管理员看全部。每一个*由父级控制*的子对象（成本计划行、工时表、差旅成本、预算调整、开票、收款、采购合同、销售订单）都跟随项目自身的可见性。

## 给项目经理的提示

- ✅ **第一次保存时把基线留空**，让 Bizcase 的数字和四条计划行进来；之后再改计划行。
- ✅ **盯着[项目成本仪表板](/zh-Hans/docs/analytics/dashboards)上的预算消耗**——到 100% 的项目就是没人能再填工时的项目。
- ✅ **最后一笔款收到后把项目置为*已关闭***；已关闭的项目仍计入仪表板的合计。
