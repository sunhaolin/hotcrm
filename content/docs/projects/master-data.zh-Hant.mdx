# 主資料 [#master-data]

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

三張小表撐著本模組的其它一切。**費率卡**（`crm_rate_card`）說明某個職級一小時值多少錢；**差旅標準**（`crm_travel_standard`）說明在某一級別的城市出差一天值多少錢；**簽約主體**（`crm_legal_entity`）是我方公司裡簽合約的那個法人。三者都在 **Master Data** 導覽群組下，該群組在應用載入時是摺疊的。

## 費率卡 [#rate-cards]

| 欄位 | 含義 |
| --- | --- |
| 名稱、職級代碼、費率標準 | 職級——*高級工程師*、*架構師*、*專案經理*……——以及它按哪種標準定價（*標準、優惠、外包*） |
| 小時費率、日費率 | 該職級的成本；小時費率是工時表和人工計畫行複製的那個數 |
| 生效日期、失效日期、啟用 | 這一列費率適用的區間；同一職級、同一標準可以按區間各有一列 |
| 備註 | 費率的前提假設 |

用在哪裡：

- **工時表**選了職級，`timesheet_rate_fill` 把小時費率複製到表上——見[工時與請假](/zh-Hant/docs/projects/timesheets-and-leave)；
- **人工服務成本行**選了職級，`cost_line_rate_fill` 把小時費率複製到行上；這條行分解成月份時，每個月都按該職級、該標準在當月生效的那一列定價——見[成本計畫](/zh-Hant/docs/projects/cost-plans)。

工時表的費率是儲存時的複製，所以改費率卡不會給任何已審批的東西重新定價。計畫月份則是在明細行儲存或重新分解時定價的；為更晚的區間新增一列，它涵蓋的那些月份會在下一次儲存其明細行時改變——這正是*費率變化*這種預算調整的用途。

## 差旅標準 [#travel-standards]

| 欄位 | 含義 |
| --- | --- |
| 標準名稱、城市級別 | 標準本身——*一線城市*、*二線城市*、*三線及以下*、*海外* |
| 住宿標準 / 天、餐補標準 / 天、市內交通 / 天、日標準合計 | 每天的各項額度及其合計 |
| 往返交通 / 人次 | 一個人一次出差的往返交通估算 |
| 生效日期、失效日期、啟用 | 標準的有效期 |

[成本計畫](/zh-Hant/docs/projects/cost-plans)上的**差旅**類費用行選一條標準，計畫就把這條行算成出差次數 × 每次人數 ×（往返交通 + 每次天數 × 日標準合計）。其它費用類型直接填預算，不用這張表。

## 簽約主體 [#contracting-entities]

| 欄位 | 含義 |
| --- | --- |
| 名稱、簡稱、統一社會信用代碼、法定代表人、地址 | 法人本身 |
| 開戶行、銀行帳號 | 客戶往哪裡付款 |
| 啟用、備註 | 是否還能被選 |

**商機**在*簽約主體*分組裡指定它的簽約主體（見[商機](/zh-Hant/docs/sales/opportunities)），所以合約還沒出現之前，投標就已經寫明由哪家公司簽約。

## 共用 [#sharing]

三張表都是**公開讀寫**：所有人都能讀，對該物件有編輯權的所有人都能改，沒有歸屬擋在中間。主資料就是這樣——一份共用的清單——這也是它們不帶按負責人篩的檢視的原因。實務中費率卡和差旅標準由 PMO 維護，簽約主體由財務維護；若貴司想收窄，管理員把 OWD 降為*公開唯讀*，只給一種權限設定檔編輯權即可。見[共用與安全](/zh-Hant/docs/administration/sharing-and-security)。

## 給管理員的提示 [#tips-for-admins]

- ✅ **要停用費率卡上的一列，清掉*啟用*並填上*失效日期***，而不是改它的費率——新的費率就是同一職級、同一標準下的新一列，一小時曾經值多少錢的歷史才讀得回來，計畫月份也才能繼續按日期解析。
- ✅ **一個法人註冊一條主體**；統一社會信用代碼是自然鍵。
