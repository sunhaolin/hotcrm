# 主数据

两张小表撑着本模块的其它一切。**费率卡**（`crm_rate_card`）说明某个岗位级别一小时值多少钱；**签约主体**（`crm_legal_entity`）是我方公司里签合同的那个法人。两者都在 **Master Data** 导航分组下，该分组在应用加载时是折叠的。

## 费率卡

| 字段 | 含义 |
| --- | --- |
| 名称、级别代码 | 岗位级别——*高级工程师*、*架构师*、*项目经理*…… |
| 小时费率、日费率 | 该级别的成本；小时费率是工时表和人工计划行复制的那个数 |
| 生效日期、失效日期、启用 | 卡的有效期；选启用中的卡 |
| 备注 | 费率的前提假设 |

用在哪里：

- **工时表**选了级别，`timesheet_rate_fill` 把小时费率复制到表上——见[工时与请假](/zh-Hans/docs/projects/timesheets-and-leave)；
- **人工成本计划行**选了级别，`cost_plan_line_fill` 把小时费率复制为单价——见[交付项目](/zh-Hans/docs/projects/delivery-projects)。

两者都是保存时的复制。改费率卡不会给任何已保存的东西重新定价：已审批的工时表保留审批时的费率，这正是财务要的行为。

## 签约主体

| 字段 | 含义 |
| --- | --- |
| 名称、简称、统一社会信用代码、法定代表人、地址 | 法人本身 |
| 开户行、银行账号 | 客户往哪里付款 |
| 启用、备注 | 是否还能被选 |

**商机**在*签约主体*分组里指定它的签约主体（见[商机](/zh-Hans/docs/sales/opportunities)），所以合同还没出现之前，投标就已经写明由哪家公司签约。

## 共享

两张表都是**公共读写**：所有人都能读，对该对象有编辑权的所有人都能改，没有归属挡在中间。主数据就是这样——一份共享的清单——这也是它们不带按负责人筛的视图的原因。实践中费率卡由 PMO 维护，签约主体由财务维护；若贵司想收窄，管理员把 OWD 降为*公共只读*，只给一种权限档案编辑权即可。见[共享与安全](/zh-Hans/docs/administration/sharing-and-security)。

## 给管理员的提示

- ✅ **要停用一张费率卡，清掉*启用*并填上*失效日期***，而不是改它的费率——新的级别费率就是一张新卡，一小时曾经值多少钱的历史才读得回来。
- ✅ **一个法人注册一条主体**；统一社会信用代码是自然键。
