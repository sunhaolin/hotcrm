# 主数据 [#master-data]

三张小表撑着本模块的其它一切。**费率卡**（`crm_rate_card`）说明某个岗位级别一小时值多少钱；**差旅标准**（`crm_travel_standard`）说明在某一级别的城市出差一天值多少钱；**签约主体**（`crm_legal_entity`）是我方公司里签合同的那个法人。三者都在 **Master Data** 导航分组下，该分组在应用加载时是折叠的。

## 费率卡 [#rate-cards]

| 字段 | 含义 |
| --- | --- |
| 名称、级别代码、费率标准 | 岗位级别——*高级工程师*、*架构师*、*项目经理*……——以及它按哪种标准定价（*标准、优惠、外包*） |
| 小时费率、日费率 | 该级别的成本；小时费率是工时表和人工计划行复制的那个数 |
| 生效日期、失效日期、启用 | 这一行费率适用的区间；同一级别、同一标准可以按区间各有一行 |
| 备注 | 费率的前提假设 |

用在哪里：

- **工时表**选了级别，`timesheet_rate_fill` 把小时费率复制到表上——见[工时与请假](/zh-Hans/docs/projects/timesheets-and-leave)；
- **人工服务成本行**选了级别，`cost_line_rate_fill` 把小时费率复制到行上；这条行分解成月份时，每个月都按该级别、该标准在当月生效的那一行定价——见[成本计划](/zh-Hans/docs/projects/cost-plans)。

工时表的费率是保存时的复制，所以改费率卡不会给任何已审批的东西重新定价。计划月份则是在明细行保存或重新分解时定价的；为更晚的区间新增一行，它覆盖的那些月份会在下一次保存其明细行时改变——这正是*费率变化*这种预算调整的用途。

## 差旅标准 [#travel-standards]

| 字段 | 含义 |
| --- | --- |
| 标准名称、城市级别 | 标准本身——*一线城市*、*二线城市*、*三线及以下*、*海外* |
| 住宿标准 / 天、餐补标准 / 天、市内交通 / 天、日标准合计 | 每天的各项额度及其合计 |
| 往返交通 / 人次 | 一个人一次出差的往返交通估算 |
| 生效日期、失效日期、启用 | 标准的有效期 |

[成本计划](/zh-Hans/docs/projects/cost-plans)上的**差旅**类费用行选一条标准，计划就把这条行算成出差次数 × 每次人数 ×（往返交通 + 每次天数 × 日标准合计）。其它费用类型直接填预算，不用这张表。

## 签约主体 [#contracting-entities]

| 字段 | 含义 |
| --- | --- |
| 名称、简称、统一社会信用代码、法定代表人、地址 | 法人本身 |
| 开户行、银行账号 | 客户往哪里付款 |
| 启用、备注 | 是否还能被选 |

**商机**在*签约主体*分组里指定它的签约主体（见[商机](/zh-Hans/docs/sales/opportunities)），所以合同还没出现之前，投标就已经写明由哪家公司签约。

## 共享 [#sharing]

三张表都是**公共读写**：所有人都能读，对该对象有编辑权的所有人都能改，没有归属挡在中间。主数据就是这样——一份共享的清单——这也是它们不带按负责人筛的视图的原因。实践中费率卡和差旅标准由 PMO 维护，签约主体由财务维护；若贵司想收窄，管理员把 OWD 降为*公共只读*，只给一种权限档案编辑权即可。见[共享与安全](/zh-Hans/docs/administration/sharing-and-security)。

## 给管理员的提示 [#tips-for-admins]

- ✅ **要停用费率卡上的一行，清掉*启用*并填上*失效日期***，而不是改它的费率——新的费率就是同一级别、同一标准下的新一行，一小时曾经值多少钱的历史才读得回来，计划月份也才能继续按日期解析。
- ✅ **一个法人注册一条主体**；统一社会信用代码是自然键。
