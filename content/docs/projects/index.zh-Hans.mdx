# 项目管理

**项目管理**模块是软件公司、专业服务公司做交付的地方，与它用来做销售的 CRM 在同一个应用、同一套元数据里。赢下的商机变成**售前项目**（投标与 Bizcase），审批通过的 Bizcase 变成带预算与成本计划的**交付项目**，项目此后花掉的每一笔——工时、差旅、分包——都落到这个项目上成为实际成本，与它开出的票、收到的款并排。

## 包含内容

| 领域 | 作用 |
| --- | --- |
| [**售前项目**](/zh-Hans/docs/projects/presales-projects) | 投标：项目角色、成本估算与报价、信息安全等级，以及售前立项审批。 |
| [**交付项目**](/zh-Hans/docs/projects/delivery-projects) | 赢单后的项目：预算基线、成本计划行、预算调整、实际成本、预算消耗与毛利——以及超预算项目禁填工时的门禁。 |
| [**工时与请假**](/zh-Hans/docs/projects/timesheets-and-leave) | 每人每项目每月的工时，按费率卡计价；已审批的请假同步进当月工时表。 |
| [**出差与差旅成本**](/zh-Hans/docs/projects/trips-and-travel-costs) | 先申请并审批出差，再对着它登记差旅成本，成本汇总到项目。 |
| [**项目财务**](/zh-Hans/docs/projects/project-finance) | 开票、收款、采购合同与销售订单，各自汇总到交付项目。 |
| [**主数据**](/zh-Hans/docs/projects/master-data) | 费率卡（岗位级别与小时费率）和签约主体（签合同的法人）。 |

## 项目生命周期

```
商机（已立项）
   │
   ▼
售前项目 ── 成本估算 + 报价 ── 审批（售前立项审批）
   │ （已通过）
   ▼
交付项目 ── 预算基线 + 自动带入成本计划行 ── 审批（交付立项审批）
   │
   ├── 工时表（已审批 → 人工实际）
   ├── 出差申请 → 差旅成本（→ 差旅实际）
   ├── 预算调整（已审批 → 当前预算）
   └── 开票 / 收款 / 采购合同 / 销售订单（→ 财务合计）
```

1. **商机立项**——商机自己带一个*立项状态*（见 [商机](/zh-Hans/docs/sales/opportunities)）；分类为招标代理或*其他*的客户、以及被人工确认列入美国 EAR 管制清单的客户，根本发不起商机。
2. **在商机上开售前项目**，估算四项成本与报价，发起审批。
3. **Bizcase 通过后开交付项目**——预算基线留空，就取 Bizcase 的总成本，并按每个成本类别各带入一条成本计划行。
4. **登记工作**——工时表、出差与差旅成本、采购——剩下的算术交给汇总。
5. **范围变了就走预算调整**；当前预算只在调整审批通过时才动。
6. **看两块仪表盘**——[项目成本与项目财务](/zh-Hans/docs/analytics/dashboards)——得到组合视图。

## 在哪里可以找到

在 HotCRM 应用里，这个家族分在三个导航分组：**Projects**（售前项目、交付项目、工时表、差旅成本、出差申请、请假申请、预算调整和项目成本仪表板）、**Project Finance**（开票、收款、采购合同、销售订单和项目财务仪表板）和 **Master Data**（费率卡和签约主体），最后一个在应用加载时是折叠的。成本计划行没有自己的侧边栏条目：它在交付项目上编辑。

## 这里的审批怎么走

这个家族里每一种可审批的记录——两种项目、工时表、预算调整、出差申请、请假申请，还有客户、线索和商机立项——都用记录页顶部的**发起审批**按钮提交，而不是去改状态字段：审批状态在表单和 API 上都是只读的。提交后记录锁定，直到审批人做出决定；结论与日期回写到记录，负责人收到通知。九条流程列在 [系统管理 › 自动化](/zh-Hans/docs/administration/automation)。
