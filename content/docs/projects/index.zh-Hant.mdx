# 專案管理 [#projects]

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**專案管理**模組是軟體公司、專業服務公司做交付的地方，與它用來做銷售的 CRM 在同一個應用、同一套中繼資料裡。贏下的商機變成**售前專案**（投標與 Bizcase），審批通過的 Bizcase 變成帶預算與成本計畫的**交付專案**，專案此後花掉的每一筆——工時、差旅、分包——都落到這個專案上成為實際成本，與它開出的票、收到的款並排。

## 包含內容 [#whats-included]

| 領域 | 作用 |
| --- | --- |
| [**售前專案**](/zh-Hant/docs/projects/presales-projects) | 投標：專案角色、成本估算與報價、資訊安全等級，以及售前立項審批。 |
| [**交付專案**](/zh-Hant/docs/projects/delivery-projects) | 贏單後的專案：預算基線、匯入的成本計畫、預算調整、實際成本、預算消耗與毛利——以及預算不夠時禁填工時的門禁。 |
| [**成本計畫**](/zh-Hant/docs/projects/cost-plans) | Bizcase 與交付專案背後的帶版本計畫：四類明細行、由它們分解出的月度台帳、凍結基線，以及作為新版本的調整 |
| [**工時與請假**](/zh-Hant/docs/projects/timesheets-and-leave) | 每人每專案每月的工時，按費率卡計價；已審批的請假同步進當月工時表。 |
| [**出差與差旅成本**](/zh-Hant/docs/projects/trips-and-travel-costs) | 先申請並審批出差，再對著它登記差旅成本，成本彙總到專案。 |
| [**專案財務**](/zh-Hant/docs/projects/project-finance) | 開票、收款、採購合約與銷售訂單，各自彙總到交付專案。 |
| [**主資料**](/zh-Hant/docs/projects/master-data) | 費率卡（職級與小時費率）和簽約主體（簽合約的法人）。 |

## 專案生命週期 [#the-project-lifecycle]

```
商機（已立項）
   │
   ▼
售前專案 ── 成本估算 + 報價 ── 審批（售前立項審批）
   │ （已通過）
   ▼
交付專案 ── 導入 Bizcase 預算 → 成本計畫 v1 + 凍結基線 ── 審批（交付立項審批）
   │
   ├── 工時表（已審批 → 人工實際）
   ├── 出差申請 → 差旅成本（→ 差旅實際）
   ├── 預算調整（已審批 → 目前預算）
   └── 開票 / 收款 / 採購合約 / 銷售訂單（→ 財務合計）
```

1. **商機立項**——商機自己帶一個*立項狀態*（見 [商機](/zh-Hant/docs/sales/opportunities)）；分類為招標代理或*其他*的客戶、以及被人工確認列入美國 EAR 管制清單的客戶，根本發不起商機。
2. **在商機上開售前專案**，估算四項成本與報價，發起審批。
3. **Bizcase 通過後開交付專案**，然後**導入 Bizcase 預算**：Bizcase 變成成本計畫 v1——四類明細行按月分解——它的總額變成凍結基線。
4. **登記工作**——工時表、出差與差旅成本、採購——剩下的算術交給彙總。
5. **範圍變了就走預算調整**；目前預算只在調整審批通過時才動。
6. **看兩塊儀表板**——[專案成本與專案財務](/zh-Hant/docs/analytics/dashboards)——得到組合檢視。

## 在哪裡可以找到 [#where-to-find-things]

在 HotCRM 應用裡，這個家族分在三個導覽群組：**Projects**（售前專案、交付專案、工時表、差旅成本、出差申請、請假申請、預算調整和專案成本儀表板）、**Project Finance**（開票、收款、採購合約、銷售訂單和專案財務儀表板）和 **Master Data**（費率卡和簽約主體），最後一個在應用載入時是摺疊的。成本計畫行沒有自己的側邊欄項目：它在交付專案上編輯。

## 這裡的審批怎麼走 [#how-approvals-work-here]

這個家族裡每一種可審批的記錄——兩種專案、工時表、預算調整、出差申請、請假申請，還有客戶、線索和商機立項——都用記錄頁頂部的**發起審批**按鈕提交，而不是去改狀態欄位：審批狀態在表單和 API 上都是唯讀的。提交後記錄鎖定，直到審批人做出決定；結論與日期回寫到記錄，負責人收到通知。九條流程列在 [系統管理 › 自動化](/zh-Hant/docs/administration/automation)。
