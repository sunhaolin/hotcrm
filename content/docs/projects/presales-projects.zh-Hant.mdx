# 售前專案 [#presales-projects]

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**售前專案**（`crm_presales_project`）就是投標：從商機立項到合約簽署之間，銷售與方案團隊做的那段工作。它掛在商機和客戶下，承載 **Bizcase**——成本估算與報價——是高階主管在開交付專案之前要審批的東西。

## 售前專案記錄存什麼 [#what-a-presales-project-record-stores]

| 分組 | 內容 |
| --- | --- |
| **專案資訊** | 名稱、別名、商機、客戶、專案類型、業務類別、計畫日期、描述 |
| **專案角色** | 客戶經理、專案經理、專案總監、專案 QA、資源報價負責人——五個人員欄位，記錄裡寫明投標的每一部分歸誰 |
| **成本估算與報價** | 人工成本、第三方服務成本、採購成本、專案費用、總成本、報價金額、毛利率、售前工時、售前人工實際 |
| **資訊安全** | 安全等級與備註——投標出門之前必須宣告的分類 |
| **審批** | 審批狀態*（唯讀）*、審批日期 |

四項成本數字是**售前專案目前[成本計畫](/zh-Hant/docs/projects/cost-plans)的彙總**——也就是它的 Bizcase，階段為 *Bizcase*——**總成本**是四項之和；**毛利率**由它和報價金額算出。這五項沒有一個是手填的：在成本計畫上做 Bizcase，數字自己跟上來。Bizcase 經**成本計畫審批**流程*審批通過*即成為目前版本，數字從審批通過那一刻起顯示；Bizcase 是整段估算——它的明細行不按月拆分，按月分解是交付計畫的事。

**售前工時**與**售前人工實際**是彙總：記到這個售前專案上、且*已審批*的[工時表](/zh-Hant/docs/projects/timesheets-and-leave)的工時和成本。草稿或被駁回的工時表一分不算，所以記錄上的數就是財務認可的數。

## 系統自動做的事 [#what-the-system-does-automatically]

### 商機選擇器只列已立項的商機 [#the-opportunity-picker-only-offers-initiated-deals]
投標只能掛在已經立項的商機上，所以**商機**選擇器只列出*立項狀態*為**已立項**的記錄——也就是 商機立項審批 流程的結論。還處在*未立項*、*提交立項*、*立項駁回* 的商機，在通過這道關之前不會出現。這與商機上按金額分檔的大額審批無關，後者不影響選擇器。

### 客戶跟著商機走 [#the-account-follows-the-opportunity]
**客戶**留空即由所選商機帶出（`presales_project_account_carry`）——客戶是商機已經記下的事實，不必再查一次。把投標改掛到另一條商機上，客戶也跟著換；除非客戶是你自己選的，那就一直保留。

## 審批 [#approval]

投標由**售前立項審批**流程審批。點記錄頁頂部的**發起審批**——*審批狀態*欄位本身在表單和 API 上都是唯讀的，沒有別的辦法改它。提交後記錄鎖定；審批發給高階主管；結論出來後回寫狀態與審批日期，並通知負責人。被駁回的投標可以改完再提。

只有**已通過**的售前專案，它的 Bizcase 才能被匯入交付專案——見[交付專案](/zh-Hant/docs/projects/delivery-projects)裡的*匯入 Bizcase*。

## 共用 [#sharing]

售前專案是**私有**的，沒有共用規則放開它：負責人看自己的，銷售經理和系統管理員看全部。透過區域規則共用給銷售代表的客戶，並不會把該客戶的售前專案一併帶來——這種客戶上的*售前專案*相關清單，代表只看到自己的那些。

## 提示 [#tips]

- ✅ **在 Bizcase 成本計畫上把每一類成本都做上，哪怕某一類是零。** 交付專案會把那份計畫匯入為它的第 1 版，沒人做計畫的類別就是沒人做預算的類別。
- ✅ **售前工時記到售前專案上，不要記到商機上。** 只有記在專案上的工時表才會彙總進售前人工實際。
- ✅ **把 Bizcase 文件作為附件傳上去。** 售前專案已啟用附件。
