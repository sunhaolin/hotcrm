# 平台技术说明（面向 IT 团队）— 讲稿

> 与《平台技术说明-IT团队.pptx》逐页对应，共 30 页；每页的讲解词也已写入 PPT 的演讲者备注。

## 1. 封面

各位好。上一次我们给业务同事演示了 40 步流程怎么在系统里跑通；今天这一场专门讲给 IT 团队：这个平台是什么结构、业务规则放在哪里、怎么和贵司的系统对接、安全和审计怎么做、上线以后怎么运维。全程讲的都是当前安装版本的实际能力，哪些是配置、哪些要写代码、哪些还没有，我会分开说清楚。

## 2. IT 团队最关心的五个问题

先把今天的提纲交代清楚：五个问题。第一，架构是什么；第二，业务规则放在哪里、怎么改；第三，怎么和外部系统对接，包括 AI 代理通过 MCP 接入；第四，安全，谁能看什么、审计怎么留痕；第五，上线和升级怎么做。一个口径贯穿全场：我讲的是已安装版本的实际行为，能力分三类，开箱即用的、平台有但要贵司环境开启的、以及今天没有的，我会标清楚。

## 3. 一句话架构：应用 = 元数据，运行时负责其余一切

一句话：应用就是元数据。左边是源码仓库，里面的对象、钩子、流程、动作、技能、界面、权限、翻译，都是 TypeScript 声明；中间的 objectstack.config.ts 把它们登记成一个栈；编译成一份 JSON 产物；运行时加载这份产物，负责存储、权限、自动化、审批、分析、消息、文件这些通用能力。下面一行是三个入口：网页控制台、REST 数据 API、给 AI 代理用的 MCP 端点。三个入口共用同一套对象、校验和权限，这一点后面讲安全时会反复用到。存储层通过驱动适配，开发用 SQLite，生产用 PostgreSQL、MySQL 或 SQL Server。

## 4. 平台组成：安装的包与声明的能力

这页是零件清单。上面一行是内核和数据层：core、runtime、spec、metadata、objectql 查询语言、formula 公式引擎、三个存储驱动、平台对象、账号、CLI。中间一行是插件和服务：认证、安全、共享、审批、自动化、分析、消息、文件存储、记录变更触发器；审计插件随 auth 一起装配；webhooks 插件平台有，本应用没启用。下面一行是应用向运行时声明的能力列表 requires，缺一项就拒绝启动。三个注意点：ai 不在列表里，因为 AI 运行时是企业版的，技能元数据本身没问题；hierarchy-security 是唯一声明的企业版能力，用于经理对下属合同的写权限，开源版上安全退化为仅本人；webhooks 想用就加一行声明。

## 5. 元数据种类一览：目录 → 注册键 → 本应用数量

这张表回答「业务规则到底放在哪」。每一行是一类元数据：目录、文件后缀、在栈里的注册键、以及本应用现在有多少。数据模型 32 个对象 574 个字段 37 条校验；51 个钩子；40 个动作；38 条流程；6 个 AI 技能；界面元数据；分析层；导入映射；安全三件套：权限集、共享规则、岗位；四个语言包；还有按环境回放的初始数据。所有这些都是文本文件，进 git、走评审、跑测试。

## 6. 第一部分 · 数据与业务规则

第一部分讲数据和业务规则。顺序是从静到动：先看对象怎么定义，再看校验和状态机，然后是钩子、流程、审批，最后是把这些串起来的动作按钮。每一层都是声明式元数据，我会用贵司 40 步里的例子来对应。

## 7. 数据模型：32 个对象，四个业务域，两种关系

这是数据模型的骨架，不是全图。上面一行是销售主链：线索、客户、商机、报价、合同。第二行往下是贵司关心的项目交付域：售前项目挂在商机下，交付项目挂在合同下；预算调整、成本计划行、工时表、差旅成本是交付项目的主从子对象，随项目级联删除、共享也随父记录走。虚线是钩子维护的业务关系：费率卡给成本计划行带出单价，已审批的请假自动同步到工时表。右边三组是服务与市场、财务与预测、主数据和平台对象。两点给 IT 同事：一是命名空间，业务对象 crm_ 前缀、平台对象 sys_ 前缀，权限和 API 是同一套；二是关系类型只有 lookup 和 masterDetail 两种，语义明确。

## 8. 一个对象的定义：字段、关系、索引与 API 开关

这是工时表对象的真实定义，去掉了注释。看几个点：sharingModel 是 controlled_by_parent，工时表的可见性跟着交付项目走；masterDetail 到交付项目，级联删除；approval_status 是 readonly，界面上只显示不能手改，只有「发起审批」按钮和审批流程能写；cost 是存储字段，由钩子算 hours 乘以 rate 写进去；最后 enable 里逐对象声明 REST 开关和允许的动词。右边是常用字段类型。IT 同事关心的是：新加一个对象或字段，就是改这个文件，表单、列表、API、MCP 工具全部随之出现，不需要动前端。

## 9. 校验与状态机：CEL 谓词声明规则，三处同样拦截

校验分两种。上面是脚本校验：一条 CEL 谓词，比如「关闭日期不能早于今天，除非商机已关闭」。注意 has() 的用法，表达式对缺字段的记录也有定义，这是我们的硬性规范，因为记录页会在数据到达前先求值一次。下面是状态机：对每个状态声明允许迁移到哪些状态，右边是工单状态机的图，越界迁移按 severity 处理，可以是拒绝也可以是警告。关键在于，同一条规则在界面、REST、MCP 三处生效，AI 代理也绕不过去。跨对象的规则放钩子，下一页讲。

## 10. 钩子 Hooks：一次保存的完整路径

这页回答「复杂业务规则写在哪」。上面是一次保存的完整路径：权限检查、校验规则、before 钩子、持久化、after 钩子，然后触发记录变更流程。三个入口共用这条路径。中间是工时表的例子：费率卡带出单价、同步已审批的请假、算成本、最后一个是预算门禁，实际成本超预算就拒绝，REST 调用方拿到 400 和结构化错误码，界面弹出中文提示。左下是拒绝信封的代码，注意它是内联在每个钩子里的，因为钩子在 QuickJS 沙箱里跑，不能引用外部模块，这保证了钩子可以纯元数据打包。右边是事件类型和约束。所有 51 个钩子都有用真实引擎跑的测试。

## 11. 流程 Flows：38 条自动化，四种触发，逐条可关

流程是平台的自动化引擎。四种触发：屏幕流程从按钮发起带表单；记录变更流程在保存后按 CEL 条件触发，贵司的九条审批都是这一类；定时流程按 cron 跑，比如 SLA 监控和预测快照；子流程被别的流程调用。右边是 Studio 里的可视化视图。三个 IT 关心的点：一是运行身份，记录变更流程用 system，因为写入可能来自集成或种子回放，没有用户会话；二是触发条件写迁移而不是状态，否则每次编辑都会重复触发，账务交接会发重复单；三是运维口径，Setup 里可以逐条关掉安装包自带的流程，或者克隆后改写。底部是 13 种节点类型，http 和 approval 两个后面单独讲。

## 12. 审批：发起是动作，流转是流程，留痕在平台对象

审批是贵司流程里出现最多的东西，这页把它拆成三块。发起是一个动作按钮，把只读的状态字段写成 submitted；流转是一条记录变更流程，图上就是它的节点：读取记录、审批节点、通过则标记并通知、驳回则标记并通知。审批节点的配置决定审批人怎么找：按岗位、按指定用户、按直属经理、或者组织所有者，找不到人时有兜底，不会卡死；决定前记录锁定。留痕在平台对象 sys_approval_request，右下是它的列表，谁发起、谁审、什么时候、什么决定，全部可查可导出。最后一点对 IT 很实用：九条审批流程是同一个模板函数生成的，新增一条审批就是一行声明。

## 13. 动作 Actions：按钮即元数据，三处同一入口

动作就是按钮，也是元数据。左边是「发起审批」的真实定义：脚本类型，在沙箱里执行，声明了 api.write 能力和 5 秒超时；locations 决定出现在记录头和列表行；visible 是一个 CEL 谓词，草稿或被驳回时才显示；确认文案、成功提示、刷新都由运行时渲染。右边的重点是「三处同一入口」：这个按钮在界面能点，REST 可以 POST 调用，打开 ai.exposed 之后 AI 助手也能以工具形式调用，走的是同一段代码和同一套权限。不可逆的动作可以要求人工确认。

## 14. 界面与多语言：视图、页面、翻译都是元数据

界面这页讲得快一些。左边是交付项目的列表，这个页面没有一行手写前端代码：导航来自 app 元数据，列表来自 view 元数据，记录详情来自 page 元数据，表单来自字段定义。多语言是四个语言包，CI 里有一道门槛要求翻译零缺失，所以不会出现半中半英的界面。控制台是平台统一的组件库，系统设置、Studio 和业务应用是同一套，Studio 可以浏览安装包的元数据。对 IT 的意义是：界面改动走的是和业务规则一样的评审、测试和发布流程。

## 15. 分析：数据集 → 报表 → 仪表板，同一套行级权限

分析层三件套：数据集定义查询，报表和仪表板消费数据集。左边是项目财务仪表板，全部由元数据声明。IT 关心的两点：一是权限，仪表板的数字受同一套行级权限约束，销售代表和总监看到的是同一份定义、不同的数；二是没有 ETL 和第二份口径，就是对象数据的实时视图，我们还有一个对账脚本在 CI 里把仪表板数字和源记录逐项核对。外部 BI 要取数，走 REST 查询或者外部数据源，第二部分讲。

## 16. 第二部分 · 接口与集成

第二部分讲接口。先讲数据 API，因为其他所有入口都建立在它之上；然后是 MCP，也就是 AI 代理怎么接进来；再讲平台自带的 AI 技能；最后是出站方向：怎么把数据可靠地送到贵司的财务、OA 系统，以及外部数据源和导入导出。

## 17. 数据 API：对象一开 API 就有，规则一个不少

数据 API 是所有入口的地基，这页的请求和响应都是今天在演示环境上实测的。第一步登录拿 cookie，无头场景用 API 密钥。第二步查询，filters 支持对象形式和数组形式，可以裁剪字段和分页，响应带总数和是否还有更多。第三步最重要：通过 API 在超预算的试点项目上新建工时表，被钩子拦下，返回 400 和结构化的 code、userMessage，和界面上看到的拦截是同一条规则。第四步是通过 API 调用「发起审批」动作，已审批的工时表被拒绝，和按钮行为一致。右边是端点表和几个限制：批量写入的一万行上限、登录限流；业务接口本身默认不限流，建议放在贵司网关。没有 GraphQL。

## 18. MCP：AI 代理以调用者自己的身份接入

MCP 是今天最想让 IT 同事记住的一页。上面的链路：左边是各种 AI 客户端，Claude、Cursor、VS Code、Codex，或者贵司自己写的代理；它们连到本部署的 MCP 端点，身份走 OAuth 2.1，部署本身就是授权服务器，用户在浏览器里登录一次，代理拿到的是这个用户自己的令牌；无头场景用 API 密钥。代理拿到的工具是平台的数据工具，加上打开了 ai.exposed 的动作。关键是最右边：每一次调用都经过和界面一样的判定，权限集、行级共享、字段级安全、审计，没有共享服务账号，没有旁路。左下是 Setup 里的「连接智能体」页面，每种客户端一键配置，还可以下载 SKILL.md 教代理怎么用本环境。两个部署提示：网页版 Claude 需要公网 HTTPS，本地客户端可以直连内网；MCP 不依赖企业版 AI 运行时。

## 19. AI 技能：六个技能只读为主，写入只走真实动作

AI 技能这页要把口径讲清楚。应用带六个技能，表格列了每个技能什么时候激活、读什么、写什么：五个是只读的，只有线索评估有写入，而且写入是通过真实的动作，转化线索这种不可逆的还要人工确认。右边是「实时数据」技能的定义，本质是一段说明加一组工具名，工具来自平台，技能自己不带私有工具。版本口径：技能的运行时在企业版，我们的开源版安装里刻意不声明 ai 能力，技能照常校验和打包，但助手面板不出现。这不影响上一页的 MCP，贵司可以先用自己的代理通过 MCP 接进来。

## 20. 出站集成与数据交换：可靠投递、数据源、导入

出站方向。上面是账务交接的真实链路：商机赢单或合同生效这个「迁移」触发流程，http 节点声明 durable，不是内联调用，而是进出站队列，由平台的投递器重试、退避、死信，每次尝试带同一个投递 ID，贵司接收端按 ID 做幂等。下面三块：左边是这条可靠 HTTP 的要点；中间是外部数据源和导入导出，Setup 里可以直接连贵司的 PostgreSQL 或 MySQL 把表同步成对象，历史数据用导入映射；右边是 webhooks，平台有这个插件但本应用没启用，原因是它只能发固定信封，带条件、带明细的通知应该用流程 http 节点。底部是选型建议。

## 21. 第三部分 · 安全与合规

第三部分是安全。三页：认证与身份，重点是哪些开关默认是关的、上线前要打开；授权分层，回答「谁能看什么」；审计、加密和脱敏。全部按已安装版本的实际行为讲。

## 22. 认证与身份：能力完整，默认保守

认证这页是一张「上线前检查表」。能力都在：scrypt 存密码、密码策略、账号锁定、登录限流、TOTP 多因素、SAML 和 OIDC 单点登录、SCIM 同步、会话控制。但默认值保守：密码策略默认关，账号锁定阈值默认 0 也就是不锁，多因素默认关，会话空闲和绝对超时默认不限。右边一列是我们的建议，最重要的一条是把锁定阈值设上。SCIM 有能力没界面，要当作部署项。右边是会话页面，管理员可以踢掉任何一个会话。

## 23. 授权分层：四层判定，外加字段级安全

授权分四层，从上到下：权限集是对象级的门，不放行就直接拒绝，后面的都不看；组织默认决定行级基线，私有、公开只读或随父记录；共享规则用 CEL 条件把口子打开给某个岗位，比如大额在途商机让销售总监可读；手工共享是记录级的。字段级安全贯穿各层，某个字段对某个权限集不可读，加上读时脱敏。右边是 Setup 里的权限集列表。岗位在这个平台是扁平的能力分发组，不是汇报树；沿汇报线放权的能力在企业版，开源版上会安全退化为仅本人。最后一句是全场反复说的：三个入口同一判定。

## 24. 审计、加密与脱敏：不可篡改，读时脱敏，落库加密

审计日志是平台对象 sys_audit_log，只追加、所有字段只读，本应用因为声明了 auth 能力自动就有。记录八种动作，记录变更带新旧值；「谁看过这条记录」的读审计从 17.1.0 起可以按需打开。几个不记录的要说清楚：失败登录、导出、AI 调用，需要的话在 IdP 或网关补。保留策略是热数据 90 天、归档 7 年。加密方面：secret 类型字段经加密提供者落库，没有提供者会拒绝写入而不是存明文；脱敏是读时显示规则，不是加密，两者要组合用。备份是数据库级，由部署侧负责。

## 25. 第四部分 · 交付与运维

最后一部分讲交付和运维：代码怎么进来、怎么被检查、怎么变成产物、怎么部署到不同环境、怎么升级回滚，最后是我们对贵司系统接入顺序的建议。

## 26. 源码即元数据：一条 PR 走完的 CI 门槛

交付的核心是：元数据就是源码，源码就在 git 里。一条 PR 要过两排门槛：源码卫生、token 只降不升、validate 跑 44 条作者时规则、lint、i18n 零缺失、typecheck；然后构建产物、跑三千六百多个用例并检查覆盖率、Playwright 真实浏览器端到端、文档站构建和链接检查、CodeQL 安全扫描；评审通过合并，再由发布工作流推到目标环境。本地一条 pnpm verify 等价于 CI。对贵司的意义：二次开发走同一条流水线，评审看到的就是全部变更，没有藏在数据库里的配置。

## 27. 部署与环境：一份产物，三种数据库，按环境种子

部署模型很简单：一份编译产物，装到哪个环境都一样，环境之间的差别只有数据库和种子。开发用内置 SQLite，测试和生产用 PostgreSQL、MySQL 或 SQL Server。种子按环境回放，主数据进生产，演示数据只进开发。构建组合在构建时决定，本次演示用的是中文组合。升级前用 os migrate plan 看元数据和物理库的差异，破坏性变更会被标出来；回滚就是重新部署上一个产物。产物声明协议主版本，运行时不符会拒绝加载。右下是 Setup 里的软件包列表。

## 28. 贵司 40 步 → 平台原语：每一步落在哪一层

这页把贵司 40 步的需求映射到平台原语上，业务同事看过演示，IT 同事看这张表就知道每一步在哪一层实现。九类审批是动作加流程加审批节点；招标代理不能发起商机是一条谓词；铁三角和项目角色是 lookup 字段加岗位；带出单价和成本计算是钩子；超预算禁填工时是跨对象门禁钩子，API 同样拦；查询和仪表板是分析层；附件和通知是平台服务；多语言是翻译包。没有一项需要写前端或改运行时。

## 29. 接入建议：三个阶段，每一步都用现成能力

最后是接入建议。中间是 HotCRM，六个方向：身份系统走 SAML 或 OIDC 单点登录加 SCIM 同步；历史数据用导入映射和 REST 批量写；财务 ERP 用可靠出站 HTTP 做赢单和合同生效的交接，开票收款回写走 REST；OA 和消息用 http 节点通知；BI 用 REST 查询或外部数据源；AI 助手用 MCP。分三个阶段：上线前把身份、数据库、主数据、权限落定；上线后一两个月做财务、OA、BI 和审计接入；第三阶段接 AI 和按需启用企业版能力。每一步都是现成能力，不需要定制运行时。

## 30. 收尾

三句话收尾。第一，应用即元数据，所有东西进 git、走评审、过 CI，一份产物装到任何环境。第二，三个入口一套规则，控制台、REST、MCP 共用同一套对象、校验、钩子和授权，AI 代理也绕不过去。第三，能力完整但默认保守，上线前按检查表把认证相关的开关打开。材料都在仓库里：这份 PPT 和讲稿、平台文档、演示环境的运行手册。欢迎提问。
