# 演示手册 — 项目型销售 + 项管平台（demo/psa-presales）

> 分支 `demo/psa-presales`，对应总纲 [#2](https://github.com/sunhaolin/hotcrm/issues/2)。
> 这是一次性演示分支：只保证 `pnpm validate && pnpm build` 为绿，**永不合并**；若立项做行业模板，这里的对象迁移到独立包。
> 截图均为本手册所在目录下的 `NN-*.png`，按下面的顺序拍摄。

## 0. 启动与登录

```bash
git checkout demo/psa-presales
pnpm install
pnpm dev            # 端口 4001；首次启动会回放种子数据，等日志安静约 20–30 秒
```

- 若启动时刷屏 `NODE_MODULE_VERSION … requires …`：`pnpm rebuild better-sqlite3` 后重启（AGENTS.md 已知坑）。
- 浏览器打开 <http://localhost:4001/_console/login>，登录 **admin@objectos.ai / admin123**（仅开发环境的种子管理员）。
- 控制台跟随浏览器语言；把浏览器语言设为 **简体中文**，界面即为中文（`00-home.png`）。
- 主页"我的应用"点 **HotCRM** 进入应用；左侧导航里有 **销售** 组和新的 **项目管理** 组。

## 3. 不要点的地方

- **设置 / 系统设置** 里的元数据校验、文档一致性之类的守卫——这条分支刻意没过 `pnpm verify`（文档覆盖、四语言、token 天花板），那里会红。
- 语言不要切到 **西班牙语 / 日语**——新对象只做了中文和英文，其余会回退到英文键名。
- 冷启动后 **不要**先在售前项目上点"提交审批"再切分支重启：审批请求存放在数据库里，改流程定义不会迁移旧请求。

## 4. 演示前自检（2 分钟）

1. `curl -s localhost:4001/api/v1/health` 返回 200。
2. 交付项目列表两行：DLV-0002 预算消耗 **132**、DLV-0001 约 **53**。
3. 项目成本仪表板四块磁贴都有数字，柱状图已画出（首次进入等 2 秒，图表是懒加载）。
4. 待我审批为空（干净状态）；随手在任一交付项目上"提交审批"一次，确认请求出现后勾选 → "通过 1 条"，记录回到已审批。

## 5. 一句话总结给客户

> 你们的 40 步流程里，客户/线索/商机/审批中心/附件/跟进/赢丢单这些 CRM 能力是现成的；售前立项、交付立项、成本计划、工时与差旅、项目成本报表这 26 步，是今天这个演示新加的五个对象、六条审批流、两条门禁和一个仪表板——**在同一个平台、同一套元数据里长出来的**，这就是它能做成软件行业模板的原因。
