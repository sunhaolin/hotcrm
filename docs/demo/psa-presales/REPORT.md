## 一、结论

客户 Excel（`CRM____.xlsx` Sheet1）共 **40 个业务步骤、9 个业务环节**。其 `系统路径` 列自身划出两个系统：步骤 1–14 属 CRM，步骤 15–40 属 `项管平台`。客户确认项管平台不存在且需要，于是本次在 HotCRM 之上，用同一套元数据把两侧做成**一条可贯通演示的路径**，并在真实运行的系统上逐项验证。

| 覆盖情况 | 步骤数 | 说明 |
|---|---|---|
| **新增开发** | **25** | 全新对象、字段、审批流、门禁；其中 3 步为简化实现（20 / 33 / 35） |
| **扩展已有对象** | 4 | 客户 / 线索 / 商机加字段（步骤 1 / 6 / 8 / 13） |
| **复用标准功能** | 3 | 平台或 HotCRM 现成能力，零开发（步骤 4 / 10 / 12） |
| **部分覆盖** | 4 | 步骤主体可演示，个别字段或数据源未做（步骤 2 / 9 / 37 / 38） |
| **未做** | 4 | 步骤 3 / 14 / 32 / 40（见第五节） |

**36 / 40 步可演示。** 代码量：14 次提交、164 个文件、+5,073 行（含第二轮）；只过 `pnpm validate && pnpm build`（分支约定，见第六节）。

## 六、架构决策与约束

1. **demo 分支不合并、不开 PR。** 仓库的源码 token 棘轮（维护者裁定的天花板，"业务逻辑 < 100k tokens"是仓库定位）在 `main` 上只剩约 695 tokens 余量，而一个对象约 1,500 tokens；本次新增约 16k tokens，不可能进入 `src/` 主线。分支只过 `pnpm validate && pnpm build`，刻意跳过文档覆盖 / 四语言 / token 守卫。
2. **行业模板放独立包。** 这套流程是项目型 IT 服务公司的标准骨架，可做"软件行业垂直版"；由同一个数字决定，它必须是叠在 HotCRM 之上的独立扩展包 + 一个 PSA 应用，demo 分支上的对象从那里**迁移**、不合并。
3. **平台能力不重造。** 组织层级（事业部 / 事业本部 / 事业群）用平台 `sys_business_unit`，审批岗位用 `sys_position`，审批 / 附件 / 时间线 / 汇总均为平台原生。
4. **实跑发现的平台事实**：分析 SQL 读不到公式字段（预算消耗率改为由两个汇总和派生）；空岗位下 `admin_rescue` 表现为记录页的"越权"按钮而非收件箱行（演示流程改为路由到组织 owner）；标准产品的大额商机审批在种子回放时就会把三条商机锁在"审批中"（种子直接把 `approval_status` 置为已通过，让演示只走客户自己的立项门）；线索页的两条"重复线索"告警在演示控制台上无视 `duplicate_status` 渲染（本分支移除，`main` 不动）；`record:details` 只渲染分组里点名的字段，新加到对象上的字段不挂进记录页就不显示。

### 9.3 本轮简化与口径

- 请假只按工作日（周一至周五）× 8 小时计；不接考勤系统；加班工时手填。

### 10.1 审批的发起是一个按钮（贵司反馈）

反馈原文：「审批的发起应该是增加一个按钮 发起审批，而不是编辑记录手动修改审批状态」。改法：

| 项 | 做法 | 元数据 |
|---|---|---|
| 按钮 | 九个可审批对象各一个记录页动作 `submit_approval`（客户 / 线索 / 售前项目 / 交付项目 / 工时表 / 预算调整 / 出差申请 / 请假申请为「发起审批」，商机为「发起立项审批」）；出现在记录页顶部与列表行菜单；只在**草稿 / 已驳回**时可见（CEL 谓词总函数化）；点击弹确认框「确认发起 X 审批？提交后记录将锁定，直到审批完成」 | `src/actions/psa-approval.actions.ts`（一个工厂生成九个动作） |
| 动作做什么 | 把该对象的状态字段写成 `submitted`——正是九条审批流监听的那次变化，所以审批请求、记录锁定、通过 / 驳回回写与通知都不变 | 沙箱脚本体，`ctx.api.object(x).update` |
| 状态只读 | 九个状态字段加 `readonly: true`：表单里看得到、改不了，REST 也写不进——状态只由按钮和审批流写 | 9 个 `*.object.ts` |
| 自定义记录页 | 客户 / 线索 / 商机详情页自带页头，动作要点名才显示；`submit_approval` 排在页头动作第一位 | 3 个 `*_detail.page.ts` |

- 演示数据仍不含市场活动、工单、知识库（标准 CRM 的服务 / 营销模块），这些不在 40 步流程里。
